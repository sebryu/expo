The dev loop

The agent iterates in two tiers. Tier 1 is seconds-fast: jest against @app/sdk-mock (in-memory scoped storage, recording fake navigation, synchronous event bus). Tier 2 is the real thing: modctl dev serves an unsigned dev manifest on localhost:8090, and the dev shell — the actual host app, downloaded once from GitHub Releases — loads the module through the exact production path: fetch → hash verify → new Function → __registerModule__ → mount.

Same path as production — by construction

The dev shell has no special loading mode. The only differences on the dev channel: the registry URL points at localhost:8090 and the ed25519 signature check is skipped (S4) — the SHA-256 hash check stays. Staging and production manifests run the identical fetch → verify → eval → mount code, ~500 lines in packages/module-loader.

Tier 2, hands-free — the agent drives the simulator itself

Inside the sandbox the agent has argent MCP (A3/S6): it boots the simulator, launches the dev shell, discovers elements, taps through its own feature flows, and screenshots the result — closing the loop without a human. The very same tooling later drives the P5 smoke test in CI, so a flow that passes here passes there.

Contract violations the mock can't catch — a forgotten capability in module.json, a design-system misuse, an accidental top-level side effect — surface here, in the real Hermes runtime, before any push.
